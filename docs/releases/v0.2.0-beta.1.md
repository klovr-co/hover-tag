# Tag v0.2.0-beta.1

This beta candidate brings together the work published across the
`v0.2.0-alpha.1` through `v0.2.0-alpha.11` releases. It has not yet completed
live Slack qualification and is not yet published.

## Slack experience

- Codex App Server is now the default transport, with streamed final answers,
  activity updates, and Slack Stop cancellation.
- Authorized owners can invoke Tag in direct messages and search approved Slack
  channel history with workspace and channel permission checks.
- Requested workspace files are delivered through private Slack links, and
  agent-generated PNG, JPEG, GIF, and WebP results can be attached to the
  originating thread.
- Backend progress refreshes the idle timeout, large completion events are
  accepted within bounded limits, and interrupted or failed Slack activity
  statuses are recovered without leaving stale working indicators.

## Setup and operation

- Guided, resumable setup can create or link a Slack app, select approved
  channels, validate credentials, configure memory scopes, and personalize the
  app name and profile image.
- One installation can manage multiple independent Tags for separate Slack
  workspaces, with isolated settings, credentials, workspaces, logs, and bridge
  state while sharing the installation-owned MFS service.
- User-editable agent workspaces live under `~/Tag/NAME` for normal installs;
  application-managed configuration, credentials, releases, and runtime state
  remain in platform application data.
- Lifecycle commands, diagnostics, readable and JSON status views, development
  reloads, per-user Codex model and reasoning settings, Fast Mode, and
  non-blocking update reminders are available through the Tag CLI and Slack
  settings.
- Reset and Slack app setup flows add identity-specific destructive-action
  confirmation, safer per-Tag cleanup, manifest migration, and recovery paths.

## Installation and releases

- Installers support stable, beta, alpha, edge, and exact-version selection,
  verify checksums and build provenance, and preserve the active installation
  when an upgrade cannot be activated.
- `tag upgrade` follows a saved channel or pinned version with rollback safety
  and optional service restart.
- Immutable numbered alpha releases and exact-commit edge artifacts now feed an
  explicit beta and stable promotion workflow. The unqualified installer keeps
  `stable` as its default and does not fall back to a prerelease.
- The documentation set now covers setup, operation, access boundaries,
  integrations, supported capabilities, and troubleshooting. A bundled setup
  skill can guide installation and first-task verification without handling
  credentials outside the Tag CLI.

## Important limitations

- The supported qualification path is Slack + Codex CLI + a local MFS server
  on macOS or Linux. Windows installation and lifecycle behavior are covered by
  CI, but live Windows Slack/backend qualification has not been recorded.
- Claude Code remains experimental and is not part of the v0.2 beta
  qualification unless separately recorded.
- Tag runs the backend with the local account's files, credentials, tools, and
  permissions. It is intended for trusted, isolated sandbox use and is not a
  production-grade security boundary or hardened multi-tenant service.
- Slack OAuth, workspace approval, and organization-wide administration remain
  manual operator responsibilities.
